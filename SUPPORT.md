# Support

## Where to ask

- **Something is broken, or behaves unexpectedly** — open a
  [bug report](../../issues/new/choose). If farsyn reported something about a
  site that turned out to be wrong, use the **false verdict** template
  specifically — it collects what's needed to reproduce a run (run id,
  evidence manifest, engine, profile, seed).
- **You want something that doesn't exist yet** — open a
  [feature request](../../issues/new/choose).
- **You have a question, or you're not sure if something is a bug** — open a
  [discussion](../../discussions) if this repository has Discussions enabled,
  otherwise open an issue; we'll relabel it if it turns out to be something
  else.
- **You found a security issue** — see [`SECURITY.md`](SECURITY.md), and
  please do not open a public issue for it.
- **You want to contribute code** — start with
  [`CONTRIBUTING.md`](CONTRIBUTING.md), which points at the real brief,
  [`AGENTS.md`](AGENTS.md).

## Before you open an issue

- Check [`docs/gaps.md`](docs/gaps.md) — it's an honest, dated log of known
  defects and unproven claims. If what you found is already listed there,
  a 👍 on the existing entry is more useful than a duplicate.
- Include the command you ran, the `--json` output if there is one (the JSON
  shape is the stable integration contract; the human-readable text is not),
  and the version of `@farsyn/engine` or `@farsyn/mcp` you're using.

## Response time

This project does not have a paid support tier or an SLA for community
issues. Maintainers read and triage issues on a best-effort basis. If you
need a guaranteed response time or a private engagement, contact
**info@xala.no** to talk about it directly.
